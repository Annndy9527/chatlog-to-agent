# 隐私边界

## 哪些东西只留在自己的设备

- 微信原始数据库、数据库副本、解密材料、联系人表、聊天导出、语音、图片和附件。
- 真人的 Relationship State、会话交接包、Cherry 会话导出、实际效果截图。
- 微信号、手机号、账号目录、精确地址、学校或单位等可用于识别当事人的组合信息。
- 模型服务的 API Key、配置文件、日志和带凭据的链接。

仓库的 `.gitignore` 使用公开文件白名单：本机 `toolchain/`、临时导出和新生成的文件默认不进入 Git。`third_party/WeChatMsg/` 中已审查的上游文件单独跟踪，新增文件仍默认忽略；检查脚本会核对它们的固定哈希。`.gitignore` 不能保护手工网页上传、强制 `git add -f`、已提交的历史或复制到其他仓库的文件。

## 使用在线模型前

在本机检查并删减聊天文本，只发送分析所需的片段。代号只是第一步；独特经历、时间、地点和上下文仍可能重新识别一个人。模型请求会把你发送的内容交给所选模型服务处理，应按该服务的实际隐私条款和当事人的合理预期决定是否发送。不要把“已脱敏”当作“可以公开”。

本项目仅提供提示词和操作说明，不会自动操作微信客户端，也不会自动发送消息给聊天对象。聊天建议必须由使用者自行判断；对方明确的拒绝和边界优先于任何模型分析。

## 准备公开时

1. 演示只使用 [完全虚构的对话](../examples/synthetic-dialogue.md)，不要替换为真人记录的“改名版”。
2. 从项目根目录运行 `python scripts/check_public.py`，再看 `git status --short --untracked-files=all`；确认候选文件都是白名单中的公开说明。
3. 人工审阅本项目编写的公开文件，核对上游源码清单与许可证，并检查文件名、图片元数据和 Git 提交历史。自动扫描不能证明不存在私人信息。
4. 若发现敏感内容已经被提交，停止推送并先处理 Git 历史；只修改工作区当前文件不能移除历史版本。
