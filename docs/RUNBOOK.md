# 使用与复核

这是一条可手动复现的工作流，不是自动登录微信或一键复制真人助手的脚本。应用界面和模型能力随版本变化，以下步骤以实际界面为准。

## 1. 准备输入

没有历史聊天也可以从 [虚构演示](../examples/synthetic-dialogue.md)开始。若要用自己的记录，先阅读[隐私边界](PRIVACY.md)，并在本机完成合法导出、核对说话人和时间、删减与脱敏。导出工具的安装和具体兼容性以 [WeChatMsg 项目](https://github.com/little-KaoKao/WeChatMsg)为准；本仓库不包含它的源码或微信进程操作脚本。

准备给模型的片段建议保留“谁说的、何时说的、是否已经发送”，去掉不影响分析的身份信息。若图片或语音不能可靠转写，就明确标记为“内容未知”，不要让模型自行补全。

## 2. 创建手机端助手

在 Cherry Studio Mobile 内配置自己选择的模型。把 API Key 保存在应用的凭据设置中。向默认智能体一起提供[创建请求](../prompts/create-assistant.md)与[系统提示词模板](../prompts/assistant-system.md)，检查它是否真的创建了新助手，并查看新助手的名称、模型与实际系统提示词。若无法自动创建，手动新建并填入系统提示词模板。

原过程文件曾建议把上游 `SKILL.md` 和 `references/` 放入知识库；另一个启动包则明确没有外挂知识库，且原版指标定义留空。本公开流程按**独立提示词助手**描述；没有验证原文件加载前，不要声称运行了原版 Chat.skill 的公式。

## 3. 开始一个会话

为一个讨论对象新建独立会话，把[Topic 启动包](../prompts/topic-bootstrap.md)填好并作为第一条消息。先发合成对话验证助手能否分清“对方说了什么”“我已经说了什么”“我准备说什么”。再检查它遇到样本不足时会不会承认不确定，遇到明确拒绝时会不会建议停止施压。

完成隐私检查后才考虑发送私人片段。不要上传整库来证明这个模板能工作；少量相关上下文通常已经足够开始。

## 4. 存档与交接

会话变长或发生重要事件后，用[交接模板](../prompts/handoff.md)生成完整 Relationship State。检查事实是否有证据、推测是否被误写成事实、拒绝与边界是否保留。新会话只带最新状态与少量近期原文；不要叠加多份相互冲突的旧状态。

## 5. 评价效果

本仓库尚无公开的对照测试。若要报告效果，至少记录应用版本、模型版本、实际系统提示词、输入范围和具体任务，并用虚构案例展示“输入 → 回答 → 人工评价”。个人一次试用的“有帮助”只能作为体验陈述，不能写成提升情商、预测对方意图或保证关系结果。
